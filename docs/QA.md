## What was run

- `go vet`, `staticcheck` (clean), `govulncheck` (nothing reachable), `gosec` (every finding triaged: real one fixed, the rest are
  false positives or deliberate: OAuth1 needs SHA-1, the legacy ModernWMS hash is MD5, exports honour the umask, plugin scripts must be 0755).
- The full suite, with `-race`, on every package; 12 fuzz targets, 40 s each (FTS query, both CSV importers, catalog loader, set numbers,
  BrickLink decode/signer/item numbers, picture decode/render, ANSI to HTML, plugin names, release extraction), no crashers.
- Real data: the whole Rebrickable download (1.4 M inventory rows, 25 s, 114 k elements) into a scratch database; search 50-80 ms even while a
  refresh is writing.
- An interactive walk over a raw-socket **telnet** client (IAC negotiation, NAWS, ANSI emulator), keys typed one at a time, at 80x24, 80x25,
  100x30, 132x43 and 200x60, live resizes and a client that never reports a size; the same over the **web terminal** (ttyd WebSocket).
  Covered: sign-on, wrong password, 2FA (wrong and right code), lock and idle lock, offline search, colour picker, add and update a part,
  add a set, detail pages with a real picture, missing parts, what can I build, history, F9 undo, Ctrl-K/F2 palette, F1/F2/F6/F9/F10 in
  three key encodings, BrickLink lookup and price, settings masking, plugin hooks (run as `nobody`, audited), alert monitor notifications.
- 30 concurrent telnet sessions with abrupt disconnects (no leaked processes), per-address throttle (session cap and sign-in block), 12
  concurrent CLI writers, a catalog refresh with readers and writers at the same time.
- CLI sweep: search, stats, history, snapshots, restore round trip, import (including hostile files), exports, value, watch, BrickLink commands,
  backup, doctor, plugin, version, update check, docs generation; `mkdocs build --strict`.

Everything above ran against scratch data with **fake** Part-DB and BrickLink servers. Nothing touched production.

## Still unverified (needs real credentials or environments)

- **BrickLink live API**: endpoint shapes, `TOKEN_IP_MISMATCHED` handling and price-guide fields are built from third-party clients and verified only against fakes. The OAuth signer is verified against RFC 5849 and a published known-answer vector. Needs the user's four API values for a live check.
- **Part-DB REST API writes** (inline lots, 422 body shape, page-size cap): verified only against the fake API. Needs the user's Part-DB Edit token.
- **Real telnet clients** (PuTTY, Windows `telnet.exe`, macOS/Linux `telnet`, Termux): the protocol and key encodings were exercised with a
  raw-socket client, not with each program.
- **Terminal graphics (Kitty/Sixel)** are deliberately not built; pictures are half-block or ASCII text, which is what works over telnet.
- **The upgrade of the live `lego.db`** (the WAL switch, the new tables, the import of the four old files) was not rehearsed on a copy of the
  live file; the migration is covered by tests, and it needs the owner's OK to copy that file.
